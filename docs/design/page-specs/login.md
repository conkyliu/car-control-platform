## 1. 用户目标与业务场景
用户（包括平台超管、租户管理员、车队调度员与售后工程师）通过浏览器访问控制台，输入工号/用户名与安全密码，完成人机滑块拖拽验证，安全登入系统，获取与自身角色权限相符的 JWT 令牌与菜单视图。

## 3. 核心字段与交互规格

| 字段 / 控件 | 控件类型 | 校验与交互规则 | 默认值 / 占位符 |
|---|---|---|---|
| **用户名 (username)** | `Input` | 必填，支持 3~32 位字母/数字/下划线，自动去除首尾空格，支持回车切换至密码框 | `请输入管理员工号 / 账号` |
| **密码 (password)** | `Input.Password` | 必填，支持掩码明文切换，键盘 Enter 键直接触发提交 | `请输入登录密码` |
| **人机验证 (SliderCaptcha)** | 自定义滑块组件 | 必须滑动位移 $\ge 90\%$ 判定为通过；通过前【立即登录】按钮为禁用态 (Disabled) 或提交时高亮抖动提醒；通过后锁定为绿色并生成一次性前端安全 Ticket | 初始提示：`向右滑动完成人机验证`；成功提示：`验证通过` |
| **记住账号** | `Checkbox` | 勾选后将 username 写入浏览器 LocalStorage；下次进入自动带出并聚焦到密码框 | 默认勾选 |
| **登录按钮** | `Button (primary)` | 点击进入 `loading` 状态，防重复提交 | `立 即 登 录` |

## 4. 13 类状态与异常流程设计

1. **初始态**：检查 LocalStorage 中是否已缓存有效 AccessToken。若存在且未过期，直接静默跳转至 `/dashboard`；若不存在，加载干净登录页。
2. **提交中 (Submitting)**：按钮进入 `loading` 转圈，输入框禁用，滑块禁止二次拖动。
3. **成功态 (Success)**：
   - 提取响应中的 `accessToken`, `refreshToken`, `user`, `permissions`；
   - 存入 `useAuthStore`；
   - 顶部弹出轻量 `message.success("欢迎回来，" + user.username)`；
   - 平滑跳转至 `/dashboard`（或之前被重定向的原始目标页面）。
4. **失败态 (401 / 400)**：
   - 密码错误：提示“账号或密码不正确，连续失败 5 次将锁定 15 分钟”；
   - 账号停用：提示“该账号已被管理员停用，请联系企业管理员”；
   - 自动重置滑块验证码至初始位，清空密码框并重新聚焦。
5. **网络异常**：提示“连接服务器超时，请检查网络设置”。

## 5. API 契约与事件映射
- **提交接口**：`POST /api/v1/auth/login`
  - Body: `{ username: string, password: string }`
  - Response 200: `{ accessToken: string, refreshToken: string, expiresIn: number, user: UserInfo }`
- **刷新接口**：`POST /api/v1/auth/refresh`
  - Body: `{ refreshToken: string }`
  - Response 200: `{ accessToken: string, refreshToken: string }`

---

## 6. 验收标准 (Acceptance Criteria)
- [ ] 未完成滑块拖动时无法触发登录请求；
- [ ] 账号密码正确且滑块通过时，成功存储双令牌并进入管理后台；
- [ ] 密码错误时，能清晰友好提示并重置滑块，不发生白屏或抛出未捕获 Promise 异常；
- [ ] 勾选“记住账号”后刷新页面，用户名能够自动回显。
