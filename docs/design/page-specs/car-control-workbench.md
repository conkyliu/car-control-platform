# 试点页面规格 2：远程车控运营台与指令流水大屏 (Car Control Workbench)

> **对应需求编号**：6.1~6.10 (13 类车控指令)、6.11 (防误触确认)、6.12 (状态机流水跟踪)、6.13 (安全码校验)、7.3 (车型能力继承)  
> **优先级**：P0 核心必备 (高风险控制台)  
> **目标路由**：`/commands`  
> **归属路径**：`docs/design/page-specs/car-control-workbench.md`

---

## 1. 用户目标与典型业务场景
- **车队调度员**：在紧急场景（如司机遗忘钥匙、需要提前预热车舱空调、或在大型停车场协助寻车鸣笛）下，快速在控制台选中目标车辆，查看当前门锁/车窗/电瓶电压车况，点击对应车控指令；在二次确认或输入安全码后下发，并在 3 秒内看到实时指令从 `WAITING_ACK` 变为 `SUCCESS` 的闭环反馈。

## 3. 核心子模块与交互规则

### 3.1 车辆快速选择与全景车况卡片
- **快速选车下拉框**：支持按车牌号、VIN 码后 6 位模糊过滤；选中后立即通过 WebSocket 订阅 `vehicle:${vehicleId}` 房间，获取最新遥测数据。
- **车况指标可视化**：
  - 蓄电池电压：标明数值与健康度（$\ge 12.0\text{V}$ 绿色正常；$< 12.0\text{V}$ 黄色欠压；$< 11.0\text{V}$ 红色严重欠压）；
  - 发动机状态：已熄火 (OFF) / 运行中 (ON)；
  - 四门二盖状态：门锁（闭锁/开启）、后备箱（开启/关闭）、车窗与天窗状态。

### 3.2 13 类远程指令分级下发机制
依据《功能清单》6.1~6.10 与安全门禁决策：

| 指令代码 | 指令名称 | 安全级别 | 触发交互与二次确认要求 |
|---|---|:---:|---|
| `UNLOCK` | 门锁解锁 | **L1** | 弹出 Popconfirm 提示“确认解锁车辆门锁吗？”，点击确认后下发 |
| `LOCK` | 门锁上锁 | **L1** | 直接点击或简单确认后下发 |
| `TRUNK_OPEN` | 开启后备箱 | **L1** | 弹出 Modal 提示“后备箱开启后若无人关闭可能存在财产风险，确认开启吗？” |
| `FIND_CAR` | 寻车鸣笛双闪 | **L1** | 直接下发，默认持续鸣笛双闪 30 秒 |
| `START_ENGINE` | 远程点火启动 | **L2 (高危)** | 弹出强安全确认弹窗：选择启动运行时间（5~45 分钟，默认 15 分钟），必须输入 6 位数字操作安全码 |
| `STOP_ENGINE` | 远程熄火 | **L2 (高危)** | 弹出强安全确认弹窗：系统检测车辆车速（车速必须为 0 且挡位处于 P 档），输入安全码后下发 |
| `AC_START` | 开启空调 | **L1** | 弹窗选择目标设定温度（16°C ~ 30°C，步进 1°C）与风速档位（1~3档） |
| `AC_STOP` | 关闭空调 | **L1** | 直接确认下发 |
| `WINDOW_UP` | 一键升窗 | **L1** | 确认下发，带防夹手安全提醒 |
| `WINDOW_DOWN`| 一键降窗 | **L1** | 确认下发 |
| `SEAT_HEAT` | 座椅加热 | **L1** | 选择主驾/副驾及加热档位 (1/2/3档) |

### 3.3 实时指令执行流水监控大屏 (`CommandStreamDrawer`)
- 页面右侧常驻显示当前车辆最近 20 条指令执行记录。
- **状态流转与动画**：
  - 点击按钮后，第一行插入一条记录，状态为黄色的 `WAITING_ACK`，带有 Spin 旋转动效；
  - 收到设备 MQTT 应答后，在 300ms 内平滑过渡为绿色的 `SUCCESS`，并展示端到端全链路耗时（如 `1.28s`）；
  - 若车机拒绝，转换为橙色 `REJECTED` 并展示具体错误原因（如“车机挡位非P档拒绝点火”）；
  - 超过 10 秒未收到应答，自动转换为红色 `TIMEOUT`。
- **409 排他锁友好提示**：若上一个指令仍在等待应答中，用户再次点击同一辆车的控车按钮，前端捕获后端的 409 `VEHICLE_COMMAND_IN_PROGRESS`，弹出友好 Toast：“该车辆已有指令正在执行中，请稍候”，避免指令风暴。

## 4. 车型能力模板继承控制 (`Capability Template`)
- 页面加载时根据该车辆绑定的 `modelId` 查询对应车型的能力模板；
- 若该车型不支持某指令（如该车型出厂无座椅加热或无天窗），对应按钮置为禁用状态 (`disabled=true`)，悬停展示 Tooltip：“该车型硬件配置不支持此功能”，保障人机体验严谨。

---

## 5. API 契约与事件映射
- `POST /api/v1/commands`: 下发控车指令
  - Payload: `{ vehicleId, commandCode, params, securityCode }`
  - Response: `{ commandId, status: "WAITING_ACK", traceId }`
- `GET /api/v1/commands/history?vehicleId=...`: 历史指令分页查询
- `GET /api/v1/vehicles/:id/status`: 获取车辆实时车况
- `WebSocket: command.status`: 实时监听指令状态跃迁 (ACK 推流)

---

## 6. 验收标准 (Acceptance Criteria)
- [ ] 切换车辆时，左侧车况指标与右侧指令流水即时联动更新；
- [ ] L1 指令有清晰的防误触确认，L2 高危指令必须强制校验安全码；
- [ ] 指令下发后能够实时展示状态机跳变，且耗时计算精确至毫秒；
- [ ] 遭遇 409 并发排他锁时能自然优雅提示，不发生 UI 崩溃。
