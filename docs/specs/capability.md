# Capability Domain Specification (能力继承与解析规范)

## 1. 业务目标
不同品牌、车型乃至单车所支持的远程指令各不相同。Capability 领域负责在指令下发前，解析目标车辆对指定指令的最终支持情况、可用参数范围与安全等级。

## 2. 三级继承模型 (Inheritance Hierarchy)

```text
┌─────────────────────────────────┐
│ 1. 全局指令字典 (Global Dict)    │ -> 基础定义 (默认名称、默认超时、默认参数约束)
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ 2. 项目配置覆盖 (Project Rules)   │ -> 按所属大客户项目开启/屏蔽特定功能 (如禁开后备箱)
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ 3. 车型能力模板 (Model Template)  │ -> 对应具体款型/硬件版本的物理能力 (如无电动尾门)
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ 4. 单车能力覆盖 (Vehicle Override)│ -> 个体车辆的增量配置或特定保修/禁用状态
└────────────────┬────────────────┘
                 │
                 ▼
      [ 有效生效能力 (Effective) ]
```

## 3. 解析规则
1. 若单车配置显式指定 `supported: false`，则直接判定不支持。
2. 若单车未配置，则继承车型模板配置。
3. 若车型模板支持，但所在项目配置显式禁用，则生效结果判定为不支持。
4. 安全等级取各层覆盖中的最高级别（如全局默认 L1，车型提升为 L2，则生效为 L2）。
5. 参数校验：入参必须符合生效能力配置的参数 Schema 范围约束（如空调温度在 16-30 度之间）。
