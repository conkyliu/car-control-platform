# ADR-014: OTA 分批并发限流调度与分片断点续传架构决策

## 背景
在大规模智能网联汽车运营场景中，单个租户往往管理数万至数十万台车载终端设备。固件升级包体积通常在数十兆至上百兆字节（10MB ~ 100MB+）。在系统设计与网络传输层面面临以下严峻挑战：
1. **基础设施惊群效应与瞬时带宽洪峰 (Thundering Herd Problem)**：
   - 若系统对全量车辆发起并发无差别升级通知，成千上万台车载终端将在同一秒内向对象存储与 CDN 边缘节点发起 HTTP GET 下载请求；
   - 瞬时激增的数百 Gbps 突发流量将直接打爆 CDN 边缘带宽配额，导致 CDN 节点宕机，并产生灾难性的突发带宽账单；
   - 同时，大量设备并发建立 MQTT 会话并频繁上报下载进度，会瞬间压垮 MQTT Broker 的报文转发管道，并在云端数据库产生剧烈的写锁竞争与连接池耗尽；
2. **故障爆炸半径不可控 (Uncontrolled Blast Radius)**：
   - 无论实验室与台架测试多么严密，量产车辆的零部件批次差异、硬件老旧程度和工作环境极其复杂，新固件仍可能潜藏未知的极端缺陷（如特定总线波特率偶发死锁）；
   - 若缺乏灰度梯次下发机制，全量并发升级可能导致全车队在几分钟内集体瘫痪，造成不可挽回的运营灾难；
3. **车载移动蜂窝弱网环境频繁断流**：
   - 车载终端依赖 4G/5G/Cat-1 蜂窝网络，车辆频繁进出地下车库、隧道、立交桥与偏远无信号盲区，TCP 连接中断是常态；
   - 若固件下载缺乏分片断点续传能力，每次网络闪断都必须从第 0 字节重新下载，将造成移动流量资费成倍虚耗、电瓶电量过度消耗，并导致弱网区域车辆升级成功率极低。

---

## 决策
1. **构建梯度分批并发限流调度引擎 (Gradient Batch Concurrency Scheduler)**：
   - 升级计划将目标设备集合严格划分为可配置的有序批次，由参数 `batchSize`（批次大小，默认 100~500 台）与 `batchIntervalSec`（批次间隔时间，默认 30~60 秒）控制；
   - **流水线时序派发**：调度引擎按批次串行触发下发。每下发完一个批次，调度器进入定时休眠冷却，等待 `batchIntervalSec` 之后再激活下一批次，将原本陡峭的流量脉冲拉平为平缓可预测的阶梯平台；
   - **灰度发布策略**：支持先锋测试（1% 白名单先锋设备） -> 灰度测试（5% 样本） -> 规模扩大（20% 区域设备） -> 全量推广（100%）的渐进式灰度发布流程；
   - **自动化故障熔断机制 (Automatic Circuit Breaker)**：
     - 调度引擎实时监控当前批次设备任务的失败率（`failedDevices / batchSize`）；
     - 当失败率达到或超过安全红线阈值（默认 5%）时，系统自动将升级计划置为 `PAUSED` 熔断状态，中断后续所有批次的下发；
     - 系统自动发送 `CRITICAL` 告警至运维平台，将固件缺陷的爆炸半径死死锁在当前灰度批次内。
2. **实施基于 HTTP Range 的分片断点续传机制 (HTTP Range & Resumable Transfer)**：
   - 固件下载托管于全面支持 `Accept-Ranges: bytes` 响应头的 CDN/对象存储服务；
   - 设备端将固件包划分为固定大小的分片（Chunk，如 1MB），使用标准 HTTP 请求头 `Range: bytes={start}-{end}` 逐片拉取；
   - 设备本地持久化记录已完成分片的 offset 与临时哈希校验值；
   - 在遭遇蜂窝断网、隧道盲区或临时休眠后，设备重连网络时直接读取本地断点 offset 接续下载剩余分片，杜绝从头重传；
   - 上行进度报文上报当前分片进度（`currentChunk`、`totalChunks` 与 `progressPercent`），使云端具备分片级的透明监控能力。
3. **步进阈值节流上报与分层 WebSocket 广播 (Throttled Uplink & Layered Broadcast)**：
   - **上行节流控制**：设备端禁止高频琐碎地向 MQTT Broker 上报进度，强制实行步进节流策略（进度每推进 5%~10% 或时间间隔超过 3 秒才允许上报一次），削减 90% 以上的无谓 MQTT 报文交互；
   - **分层实时推送**：云端消费上行进度后异步更新持久化状态，并通过 WebSocket 房间路由机制（`ota-plan:{planId}`、`tenant:{tenantId}`）按需定向推送，管理控制台以极低开销实时渲染批次执行进度与设备状态分布。

---

## 结果
- **消除基础设施冲击**：梯度批次下发与步进节流彻底消除了 CDN 瞬时带宽尖峰与 MQTT 消息洪峰，系统吞吐平稳可控，大幅削减云资源带宽账单；
- **爆炸半径绝对受控**：灰度分批与 5% 失败率自动熔断机制为新固件发布提供了坚实的安全缓冲带，避免了车队大面积故障事故；
- **弱网环境韧性显著提升**：HTTP Range 断点续传使车载终端能够从容应对地下车库、隧道等弱网环境，大幅降低流量损耗并提高最终升级达成率；
- **全生命周期掌控力**：平台运营人员可随时对升级计划执行人工暂停（`PAUSED`）、恢复（`EXECUTING`）或取消（`CANCELLED`），系统控制粒度精确到批次和单车。
